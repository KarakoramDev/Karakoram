# 0054 — Native Weaviate with fixed Raft voters and community features

Status: Accepted

## Context

Weaviate combines Raft-replicated metadata with independently replicated object/vector shards. Native installation, stable member identity, authenticated access, explicit shard movement and topology-preserving recovery are required; adding a runtime alone does not rebalance data. The official release executable includes both BSD-licensed source and runtime-gated enterprise code.

## Decision

### Versions and license boundary (WEAVIATE-01, WEAVIATE-02)

Provider `weaviate` installs official linux-amd64 release tarballs, catalog-pinned to 1.40.1 (default) and 1.39.12. The native-artifact lock records downloaded size, SHA256 cross-checked against the release sidecar, upstream URL and dereferenced tag commit. Members download from upstream or an operator mirror and verify the digest; Karakoram does not redistribute the executable. Install each version under `/opt/karakoram/weaviate-<version>`; the archive has root `weaviate`, `LICENSE` and `README.md` files.

Record the mixed binary license as `BSD-3-Clause AND LicenseRef-Weaviate-Enterprise`, not BSD-only. Force `NAMESPACES_ENABLED=false`, `SELF_RECOVERY_ENABLED=false`, `BACKUP_DEDUPE_ENABLED=false`; never supply `LICENSE_KEY`, `LICENSE_KEY_FILE` or backup `dedupeReplicas`. Typed options and an explicit inference-variable allowlist prevent raw environment injection. Ordinary replication, movement, RBAC, DB users and full S3 backups are community features; this boundary does not grant enterprise rights.

### Membership and replication (WEAVIATE-03, WEAVIATE-04)

`single` has one member and voter, bootstrap expect 1, and cannot scale into a cluster in place. `cluster` has 3–9 data members and exactly three fixed initial voters. Every member receives the same ordered three voter `name:raft-RPC-port` entries and bootstrap expect 3; later members actively join as non-voters. The first three candidates must be present for fresh bootstrap. Persisted Raft configuration remains authoritative afterward; bootstrap expect is not a quorum override.

Use stable member hostnames `<cluster>n<index padded to six digits>x` (for example `vectorsn000000x`), with a terminal letter preserving disjointness even after the numeric width is exhausted. Persist a monotonic next-index high-water mark and never reuse retired indices. Upstream 1.40.1 selects voters using **substring matching** of the local name against the first bootstrap-expect join entries, not exact-name membership; names must be substring-disjoint. Generated member and volume (`<member>v`) hostnames fit the backend's 25-character lowercase-alphanumeric limit. Gossip join addresses use voter hostnames and the gossip port. Replace a voter using its existing name and volume identity; never automatically demote or retire a voter.

Minimum collection replication defaults to 1 for single and 3 for cluster, bounded by member count. Explicitly enable `REPLICA_MOVEMENT_ENABLED=true`; the switch still exists in 1.40.1. Async repair remains enabled unless `ASYNC_REPLICATION_DISABLED=true`. Scale-out does not rebalance existing shards. Scale-in removes only highest-index non-voters, never below three. Reject a drain with no eligible target not already hosting the shard, including replication factor equal to member count.

Drain each replica with `POST /v1/replication/replicate` using lower-camel `collection`, `shard`, `sourceNode`, `targetNode`, `type:"MOVE"`; persist returned `id` and poll `status.state` until `READY`. Retryable native status errors retain that ID; only cancellation or a missing operation consumes a MOVE failure attempt. Recover lost POST replies from the operation list rather than submitting duplicates. After empty sharding/verbose-node observations, checkpoint a reversible process stop, retaining runtime and volume. Wait for every surviving member's `/v1/nodes` view to exclude the departing member from healthy placement, then take a fresh collection-wide sharding scan, including HOT/COLD tenant physical shards. If ownership appeared during stopping, checkpoint configuration restore, restart and readiness acknowledgement, then resume draining. Only a fenced, authoritative empty scan permits authenticated **internal data-port** `/v1/cluster/remove` with `{"node":"name"}`, followed by runtime and volume deletion. Gossip failure detection/Leave removes live membership but does not remove persisted Raft peers; a stopped voter still counts toward quorum.

### Authentication and TLS (WEAVIATE-05, WEAVIATE-06)

Disable anonymous access; enable API keys, RBAC and dynamic DB users. Static `karakoram-admin` is the sole bootstrap/root identity; its secret is revealed only through protected credentials access. Native key validation permits multiple distinct keys for one user, so rotate static keys with old+new during a rolling restart and remove old in a second roll. Application users and custom roles use native REST management; protect the root identity and built-in roles. OIDC is not configured.

Generate shared `CLUSTER_BASIC_AUTH_USERNAME`/`CLUSTER_BASIC_AUTH_PASSWORD` for internal HTTP and inter-node replication clients. Upstream also applies these credentials to internal replication gRPC services, including FileReplicationService on the client gRPC listener. They do not authenticate gossip/Raft or encrypt transport. Do not expose internal ports publicly.

Upstream accepts exactly one internal username/password, so members with different internal passwords cannot talk to each other. Rotating the internal credential therefore stops all members, applies the new credential to every member and starts them together after a healthy, synchronized quorum check; the operation reports the brief unavailability. Root-key rotation stays a two-phase rolling restart.

Default TLS is `requireTLS`, with self-signed or user-provided CA; `disabled` is explicitly private-only. REST is HTTPS-only: `--scheme https --tls-port 8080 --tls-host <bind> --tls-certificate <file> --tls-key <file>`. Client gRPC uses `GRPC_CERT_FILE`/`GRPC_KEY_FILE` on 50051. Include member hostname, localhost, loopbacks and published names/IPs in SANs. **Both listeners load certificates at startup: replacing PEM files requires a rolling restart.** TLS PEM material lives in the common encrypted member-config TLS envelope, not duplicated in the engine spec.

Expired native leaves may recover through the normal quorum-gated rolling workflow. Control-plane rolling observation allows an expired certificate only when its DER bytes exactly match the recorded active member leaf and that same durable roll includes a valid replacement leaf for the member; TLS rotation uses pinned observations for its replacement preflight as well. Agent recovery readiness also pins the active member leaf. Both retain CA-chain, server-usage and hostname verification at the leaf's validity midpoint. Desired replacement secrets are not pin authority. Ordinary readiness and native mutations remain strict; status marks expired members unhealthy with an explicit certificate-expired condition. The exception does not waive readiness, voter or synchronization gates.

Default private ports are gossip 7946 TCP **and UDP**, data 7947 TCP, Raft 8300 TCP and Raft RPC 8301 TCP. The stock memberlist transport is not TCP-only. Internal transports are plaintext; require a suitable private/encrypted backend network and do not set `CLUSTER_ADVERTISE_ADDR` for normal LAN operation. Public REST/gRPC require TLS. Set `GO_PROFILING_DISABLE=true` and `DISABLE_TELEMETRY=true`. Prometheus 2112 binds wildcard upstream with no host option; omitting a public deployment port is not a firewall. Enforce private network policy and scrape locally.

Derive the REST/gossip bind host from the backend private address family: IPv4-only Nomad and Dokploy layouts use `0.0.0.0`; IPv6 Zerops and default/dual-stack layouts use `::`.

### Backup and recovery (WEAVIATE-07)

Enable `backup-s3` whenever an S3 storage is bound (upstream refuses to start the module without a bucket); bind at most one S3 storage. Render `BACKUP_S3_BUCKET`, `BACKUP_S3_PATH`, `BACKUP_S3_ENDPOINT` (host[:port], no scheme), `BACKUP_S3_USE_SSL`, `AWS_REGION`, `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` from encrypted configuration. Storage changes require a roll. Reject operations naming another storage. Isolate keys under `<storage-prefix>/<namespace>/<cluster>/<cluster-UID>` and record immutable location, native backup ID, source version and ordered member names/count.

Only full backups are offered: no incremental chain, enterprise deduplication or PITR. GET-before-POST resolves replay; poll create to SUCCESS/FAILED/CANCELED rather than equating submission with success. Native config override fields are capitalized `Bucket`, `Path`, `Endpoint` in **both** supported versions. Restore uses top-level `node_mapping` with `config.rolesOptions`/`config.usersOptions`; values `all` restore identities in place, `noRestore` preserves fresh clone identities. Target storage endpoint/bucket and member count must match the backup, mapping names by index; this is not resharding. In-place restore explicitly deletes existing collections first. Restore only into the same or newer supported version and resolve unknown submissions by status lookup. Native cancellation is not object purge: delete retained full-backup objects with the generic storage client under the recorded backup prefix.

The `Endpoint` field is present in those schemas but is not an effective endpoint switch in the ordinary backup implementation: the S3 client uses its startup endpoint and applies per-operation bucket/path overrides only. Keep endpoint selection in the bound member environment; never use a request field to bypass storage admission.

Native restore status is keyed by backup ID and survives earlier restores of the same backup, and the status API omits attempt timestamps. Acquire durable source-backup ownership bound to target, restore and operation before capturing the baseline or deleting collections; concurrent targets wait. Terminal restores/operations or deleted targets allow atomic reclamation, and a stale release cannot remove successor ownership. Record the attempt identity (`startedAt`) from the backup's `restore_config.json` in object storage. After a crash, a different identity is this fenced attempt and may be adopted; an unchanged identity without a recorded acceptance is re-submitted; a missing or ambiguous identity fails closed with operator guidance. Identity comparison does not assume monotonic native clocks. External native restore clients must not concurrently use the same source backup, because they bypass this control-plane fence. Native backup status reports size in GiB; convert it to bytes.

### Maintenance, modules and resources (WEAVIATE-08, WEAVIATE-09, WEAVIATE-10)

Roll one member at a time, non-voters before voters; require all expected members ready and healthy, synchronized cluster statistics, expected voter configuration and a leader/quorum before each disruption. Acknowledgements include applied config version and native version. Allow patch-forward and exactly one minor forward; reject downgrade/minor skipping. Certificate updates join other restart-required configuration in the roll fingerprint.

Force `API_BASED_MODULES_DISABLED=true`; explicitly enable `backup-s3` plus the verified module allowlist shared in `wvspec`. API provider keys remain client request headers, never persisted by Karakoram. Local inference accepts only verified HTTP(S) endpoint variables, no credentials/query secrets and no arbitrary environment names. Supported process mappings include transformers, CLIP, reranker-transformers, BIND, neural image, model2vec, GPT4All, NER, QNA, summarization and spellcheck; the vocabulary is common to both supported versions. **Ollama modules use collection/request `apiEndpoint`, not a process environment variable**, and therefore are not exposed as process-inference options. Do not invent an Ollama environment variable. Default vectorizer selection belongs to collection configuration; 1.40 ignores `DEFAULT_VECTORIZER_MODULE`.

Set `LIMIT_RESOURCES=false`, GOMEMLIMIT to 85% of member RAM and GOMAXPROCS to allocated CPU (at least one). Minimum RAM 1 GiB, default 2 GiB; default disk 10 GiB. Default query result limit 25; disk warning 80%, readonly 90%, with `1 <= warning < readonly <= 95`. Persist under `DATA_DIR/weaviate`, separate from versioned executables.

Reconciliation follows the shared engine rules. A deployment whose platform retry budget is exhausted records the durable deployment fence and releases its receipt; raising `retryEpoch` redeploys under the same owner. Every queued backend mutation (stop, resource change, scale-down stop, coordinated rotation restart, runtime-recovery import, route deletion) revalidates the current service against its recorded ID or ownership marker immediately before execution. Cleanup checkpoints secret deletion after proving runtimes and volumes absent, so replay never needs already deleted agent credentials.

Public listener reservations are namespace- and cluster/member-owned, including allocations not yet published. Release them only after runtime/public-route teardown succeeds (also on secret-cleanup replay); failed backend mutations retain exclusion. Keeping volumes suspends the cluster without reserving listener ports: clear assignments and allocate afresh on resume. Disabling exposure releases only that member's owned reservations, never a successor owner's port named by a stale checkpoint.
Stored assignments contribute occupancy only to the current allocation; they never become permanent in-memory reservations. Thus a worker observing an old stored checkpoint between release and persistence cannot resurrect a retired allocation, while unpublished allocations retain their independent exclusion.

### Monitoring and member contract (WEAVIATE-11, WEAVIATE-12)

The dependency-free `internal/engine/weaviate/wvspec` is shared by provider and agent. It contains explicit HTTP, gRPC, gossip, data, Raft, Raft RPC and metrics ports so loopback tests can allocate disjoint ports; typed settings/secrets; validated modules/inference; optional S3 binding; and restart token. Rendering remains agent-owned. Keep serialized changes additive and preserve omitted-field behavior; do not rename fields or reinterpret existing values. Engine/process are both `weaviate`. Test/development hooks in the agent environment only: `KARAKORAM_WEAVIATE_INSTALL_ROOT` replaces the `/opt/karakoram` install root, and `KARAKORAM_WEAVIATE_LOCAL_CLUSTER=true` renders upstream localhost cluster mode so several members can share one network namespace with distinct ports; production runtimes never set either.

Bounded POST `/v1/weaviate/readiness` returns ready, configVersion, version and a redacted message. Native readiness combines `/v1/.well-known/ready`, `/v1/nodes?output=verbose` and `/v1/cluster/statistics`. Raft counters in statistics are strings, voter suffrage is numeric (0), and empty databases legitimately have null shard lists/zero shard counts. Count actual voters rather than `numPeers`, which excludes self. Retained-volume recognition requires native regular files `raft/raft.db` and `schema.db`, observed after authenticated first start and clean SIGTERM.

Scrape Prometheus locally with bounded responses. Export only `wvspec.MetricNames`: availability, objects, shards, collections, query/request/batch-object counters, vector-index capacity/tombstones, LSM bytes and async queue length. Exposition names use `karakoram_weaviate_`; provider descriptors map them to canonical dotted `weaviate.*` names with explicit units and scale. The provider catalog and agent share that fixed vocabulary; no arbitrary upstream labels or metrics are relayed. Version remains a native status observation, not a fabricated metric; no disk-readonly series is advertised without a corresponding native source.

### Testing (WEAVIATE-13)

Use validation/unit tests and fake-native-API provider tests for durable replay, topology, authorization and redaction. Build-tagged native integration tests exercise authenticated singleton and three-member loopback formation, RBAC/DB users, TLS, S3 backup/restore and rolling 1.39.12→1.40.1 upgrades with official binaries supplied explicitly. Native S3 tests require an external test endpoint; no Docker dependency. Live backend acceptance remains a separate gate, including UDP/private network behavior.

## Consequences

Fixed voters bound metadata quorum size but make voter identity preservation an operational requirement. Shard draining, separate Raft removal, two-step static-key rotation and topology-preserving restores cost more than replacing runtimes. Client TLS does not imply encrypted cluster transport. Mixed-license binaries require an explicit community boundary. Successful single-node startup is evidence for native packaging/layout, not proof of multi-node, upgrade or backup correctness.

## Alternatives considered

- **Container-only or rebuilt executable:** unnecessary; official pinned native tarballs support the required runtime and integrity checks.
- **All members as voters or inferred voter identity:** increases quorum exposure and conflicts with verified bootstrap semantics.
- **Scale-in by stopping a runtime:** leaves shard ownership and persisted membership behind.
- **Anonymous/static application identities:** weak security or restart-bound application key management; use dynamic DB users.
- **Hot TLS file replacement:** upstream loads certificates once; use ordered restarts.
- **Raw environment/module passthrough or invented Ollama env:** bypasses the license boundary or renders ineffective configuration.
- **Live volume copies, topology-changing restore, incremental retention/PITR:** unsupported recovery promises or additional dependency management beyond full native backups.
